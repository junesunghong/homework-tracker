이 절차로 현재 세션의 **변경·결정·미완 작업**을 포착하고, 다음 "작업 시작"이 **어떤 환경에서든** 그대로
이어갈 수 있게 마무리한다. `작업시작`의 **대칭 짝**이다.

핵심 원칙 — **환경 간 이동 매체는 git이다.** `_snapshot/` 은 git-tracked 이고, 다른 환경은 `git pull` 후
"작업 시작"이 최신 스냅샷의 "다음 단계"를 읽어 이어간다. 반면 per-project 메모리(`~/.claude/projects/...`)는
junction이 안 걸린 경우 **machine-local 이라 동기화되지 않는다.** 따라서 **이어가는 데 필요한 사실은 반드시 git-tracked(스냅샷/CLAUDE.md)로 보낸다.**
종료 직전 회사/개인 비혼합 가드레일을 한 번 더 확인한다.

## 0) 용도 확정 (회사 / 개인) — 작업시작과 동일

- 현재 레포의 `CLAUDE.md`(없으면 도메인 단서)로 **자동 판별**: 회사/MailAgent/Mirero/gw.mirero/사내 URL·자격증명 → **회사**, "개인용/회사무관"(예 WebCrawler) → **개인**. 단서 없으면 질문.
- 이후 **§3 메모리 라우팅 · §4 푸시 리모트 · §5 가드레일은 모두 이 용도로 분기**한다. (작업시작의 §1·§3과 대칭)
- **방금 처리한 요청(들)의 용도를 쓴다** — 작업시작 §1-1의 요청 단위 판별과 대칭. 머신은 한 대로 고정이어도 요청 용도는 매번 다를 수 있다.

## 0-b) 체크포인트(중간 저장)와 종료(마무리)  ← v2 신설 · v2.3 일반화

**체크포인트는 특정 환경 전용이 아니다.** 어느 환경에서든, 작업을 끝내지는 않았지만 지금까지의 변경을
git에 밀어 넣어야 할 때 쓴다. 이것이 없으면 한 작업이 그 머신에 갇혀 **machine-local 문제가 재발한다.**

**모바일에서 조종할 때 특히 자주 쓰게 된다** — 이동 중에는 작업이 자연스럽게 중간에 끊기기 때문이다.

### 세 동사와 작업 상태 (v2.2)

**체크포인트는 종료의 대체물이 아니라 중간 저장이다.** 정상 흐름은 이렇다.

```
시작 → 체크 → 체크 → 종료      (일반)
시작 → 종료                     (짧은 작업)
시작 → 체크 → (중단)            (허용 — 열린 채로 남음)
```

| 동사 | 수행 범위 | 스냅샷 파일명 | 남는 상태 |
|---|---|---|---|
| `체크포인트` / `체크` | §1→§2→§4 **축약** (코드만) | `YYYY-MM-DD-HHMM_<slug>.ckpt.md` | **열림** |
| `작업종료` | §1~§5 **전체** (코드+메모리+가드레일) | `YYYY-MM-DD_<slug>.md` | **닫힘** |

- **상태 판정 근거는 해당 레포 `_snapshot/`의 최신 파일 확장자**다. 별도 상태 파일을 만들지 않는다. 상태는 **레포 단위**다.
- **`체크`·`종료`는 `시작` 없이도 수행한다.** 레포만 확정되면 된다. 시작을 강제하지 않는다.
  - **레포는 보통 `cwd` 가 정한다** — `git rev-parse --show-toplevel` 이 성공하면 그 최상위가 레포다(`작업시작` §2). **미바인딩일 때만** 결정 순서를 쓴다 — ①메시지 → ②대화 승계 → ③ **기본값 `WorkSession`**(되묻기 0). **레포를 비운 채로 진행하지 않는다**: 스냅샷을 쓸 곳(`<레포>/_snapshot/`)도 푸시할 origin 도 없어 §2·§4 가 성립하지 않는다. 2026-08-19 에 루트 세션이 git 밖 폴더를 작업해 **스냅샷이 한 건도 남지 않은** 사례가 그 모양이다.
    - ⚠️ v2.5 까지 있던 **④「후보 목록 선택」·구 ③「최신 스냅샷 제시」는 v2.6 에서 삭제됐다** — 서버 모드 잔재이고 되묻기만 만들었다(`작업시작` v3.1 §2).
    - ⭐ **미바인딩(`E:\` 루트)은 「새 Repo 가 필요한 작업」이라는 뜻이다** — 폴더가 아직 없어 거기서 세션을 열 수 없고, 상주 서버가 없어 모바일에서 새 세션을 못 만드니 그 진입점이 루트 세션이다. 새 레포가 아직 안 정해졌어도 **기록은 남아야 하므로** 기본값 `WorkSession` 으로 귀속시킨다(`작업시작` v3.3 §2).
    - ⛔ **`E:\` 하위의 진행 중인 레포 작업은 루트 세션에서 하지 않는다 — 각자 세션이 원칙이다.** 종료 시 레포가 `WorkSession (루트 세션 기본값)` 인데 실제로 만진 것이 **다른 레포의 진행 작업**이라면, 그건 원칙 이탈이므로 배너에 적고 다음 단계에 **"그 레포에서 세션을 열어 이어갈 것"** 을 남긴다.
- **체크만 하고 멈추는 것은 정상이다.** 코드는 이미 `main`에 전파됐다. 빠진 것은 **§3 메모리 반영**뿐이며, 그 누락을 다음 `작업시작`이 감지해 안내한다(작업시작 §4 참조). **차단이 아니라 권고다.**
- **종료의 고유 가치는 §3 메모리 반영이다.** 체크포인트를 아무리 많이 해도 메모리는 갱신되지 않는다 → 다음 세션이 **낡은 메모리를 근거로 판단**한다. 안내·보고 문구는 이 사실을 근거로 쓴다.

- **트리거** (어느 하나라도 해당 시):
  1. 사용자가 `체크포인트` 또는 `작업종료`라고 지시
  2. 하나의 요청 처리로 **의미 있는 변경**(커밋 가치가 있는 코드/문서 변경)이 발생해 전달을 마쳤을 때 — 시키지 않아도 **먼저 제안한다**
  3. 마지막 체크포인트 이후 미커밋 변경이 있는 채로 **유휴가 길어질 때** (그 주기가 곧 RPO — 머신 장애 시 손실 허용치)
  4. **대화를 다른 레포로 옮기기 직전** — 미커밋 변경이 있으면 "체크포인트 후 옮길까요, 그냥 옮길까요?"를 확인하고, 그냥 옮기면 ⚠️ "미전파 변경 남음"을 명시한다
- **체크포인트 절차** = 본 문서 §1→§2→§4를 **축약 실행**:
  - §1 변경 검토(요약 1–3줄·미완 분리·테스트 상태) → §2 스냅샷(파일명은 `YYYY-MM-DD-HHMM_<slug>.ckpt.md`로 구분) → §4 커밋·푸시 + **HARD-GATE 검증**
  - §3 메모리 반영·§5 가드레일은 **사용자가 명시적으로 `작업종료`를 지시했을 때만** 전체 수행(일상 체크포인트에서는 생략)
- **푸시 확인 규칙 완화**: 체크포인트 푸시를 매번 확인받으면 모바일 사용성이 무너진다 → **스냅샷+기존 추적 파일의 커밋·푸시는 사전 승인된 동작**으로 간주하되, 새 파일 추가·대량 변경·강제 푸시는 기존 규칙대로 확인받는다. (위험작업 사전확인 원칙과의 절충)
- **결과 보고**: 체크포인트 배너(§5 축약형)로 답한다. HARD-GATE 실패 시 ⚠️ **"스냅샷 미전파 — 다른 환경에서 이어갈 수 없음"**을 즉시 알린다.
- 이하 §1~§5가 원 절차이며, 체크포인트는 위 축약 규칙으로 이를 재사용한다.

## 1) 세션 요약 · 변경 검토

- 변경을 객관적으로 수집한다.
  - `git status -s` — 미커밋 변경
  - `git diff --stat` — 변경 규모
  - `git log origin/main..HEAD --oneline` — **미푸시 커밋**
- 이번 세션에서 한 일을 **1–3줄로 요약**하고, **미완(INCOMPLETE) 항목을 분리해 나열**한다.
- 테스트 상태를 **통과 / 실패 / 미확인** 세 값 중 하나로 기록한다. 실패·미확인·미커밋이어도 **종료를 멈추지 않되 배너에 ⚠️로 표시**한다.
- 산출물 저장 위치가 개인 Drive 폴더(`.env`의 `PERSONAL_GDRIVE_FOLDER_ID`)인지 가볍게 확인한다.

## 2) 스냅샷 마무리 (snapshot-archive 재사용)

- 템플릿을 재구현하지 말고 **`snapshot-archive` 스킬을 호출**해 `_snapshot/YYYY-MM-DD_<주제-kebab-case>.md`
  (같은 날 충돌 시 `YYYY-MM-DD-HHMM_...`, **체크포인트는 `YYYY-MM-DD-HHMM_<slug>.ckpt.md`**)를 작성한다. 그 스킬은 read-only·무결정·무-git 이므로, git은 4)에서 이 절차가 책임진다.
- **스냅샷 최상단에 `세션 컨텍스트` 헤더를 남긴다** — 머신(회사 PC/집 PC/클라우드)·**조종**(회사/집/이동 중/미상)·환경(**PC / 클라우드(Web 폴백)**)·용도(업무/개인)·진행시각·**직전 세션(머신·환경·시각)**. 이게 다음 `작업시작`이 *"직전 작업이 어느 머신에서·어떤 환경에서 진행됐는지"*를 확인하는 근거이자, 환경을 건너 이동되는 유일한 출처다.
  - ⚠️ **`조종` 은 사용자가 말했거나 승계된 경우에만 적는다.** 근거가 없으면 `미상` — **묻지 않는다**(`작업시작` §1-3). 이 값이 있어야 다음 세션이 *"그때는 원격이라 재부팅을 못 했다"* 를 안다.
  ⚠️ 스냅샷은 4)에서 **실제로 커밋·푸시돼야** 비로소 이동 가능하다. 본문에 "git-tracked"라고 **적는 것만으로는 전파되지 않는다** — 단정하지 말고 4)에서 검증한다. (커밋 안 된 스냅샷은 orphan으로 남아 다른 환경에서 안 보인다.)
  예: `> 세션 컨텍스트 · 진행 2026-08-25 18:00 · 머신 회사 PC · 조종 미상 · 환경 PC · 용도 회사 · 직전 회사 PC·PC(2026-08-22 17:44)`
  예(원격): `> 세션 컨텍스트 · 진행 2026-08-22 17:44 · 머신 회사 PC · 조종 집 · 환경 PC · 용도 회사 · 직전 회사 PC·PC(2026-08-21 18:25)`
  예(폴백): `> 세션 컨텍스트 · 진행 2026-08-13 14:20 · 머신 회사 PC · 조종 미상 · 환경 클라우드(Web 폴백) · 용도 회사 · 직전 집 PC·PC(2026-08-12 22:10)`

  ⚠️ **구판 헤더(`위치 …`, `조종` 없음)는 고치지 않는다.** 2026-08-25 이전 스냅샷은 그 시점의 사실이다 — `작업시작` 이 `위치` 를 `머신` 으로 읽고 `조종` 은 `미상` 으로 본다.
  ⚠️ **구판 스냅샷의 옛 환경 값**(`PC(Local)`·`PC(Remote Control)`·`Hermes(Slack)`)**은 그대로 읽는다.** 과거 헤더를 소급 수정하지 않는다 — 그때의 사실이다. 새로 쓰는 것만 2값으로 적는다.
- 8개 섹션 중 **"다음 단계"의 품질을 최우선**으로 한다: 이전 대화를 모르는 새 Claude가 **첫 명령부터 단독 실행**할 수 있도록
  구체적·즉시실행형으로, **절대경로**로 적는다. 1)에서 식별한 미완·실패 항목을 그대로 반영한다.
- ⛔ **"다음 단계"는 이 레포의 일만 적는다.**   ← v2.7 신설
  - 스냅샷은 **다음에 이 레포를 여는 사람이 읽는다.** 다른 레포·다른 폴더(`D:\Work\...` 등)의 일을 적으면 **그 사람에게 남의 일을 시키는 것**이고, *"각 레포 일은 각자 세션"* 원칙(`작업시작` §2)을 **스냅샷이 깨뜨린다.**
  - 이 세션에서 **다른 레포를 건드렸다면** 그건 원칙 이탈이다 — 그 사실을 §5 배너에 적고, 다음 단계에는 **"그 레포에서 세션을 열어 이어갈 것"** 한 줄만 남긴다. **그 작업의 상세를 여기 옮겨 적지 않는다.**
  - ⚠️ **실사례(2026-08-26)**: `WorkSession` 스냅샷이 `D:\Work\...\기술부채` 의 A-DMS 회의를 **「다음 단계」 최우선**으로 실었다. 그러면 다음에 `WorkSession` 을 여는 사람에게 **"A-DMS 부터 하라"** 가 뜬다. 그 일은 그 폴더에 **자체 `_snapshot/` 이 이미 있어** 거기서 세션을 열면 알아서 나온다.
- machine-local 경로(`~/.claude/...`)에 의존하는 항목은 스냅샷 안에서 **"이 PC 전용"** 으로 표시한다.

## 3) 메모리 반영 (이동성 + 용도 분기)

세션에서 나온 **지속성 있는**(일회성 아님) 사실을 종류별로 **올바른 위치**에 기록한다. 기록 전 사용자에게 항목·위치를 제안한다.

**공통 (용도 무관)**

| 사실의 종류 | 가야 할 곳 | 이동 여부 |
|---|---|---|
| 재개에 필요한 진행상태·다음 단계·함정 | `_snapshot/*.md` (2번) | ✅ git-tracked → 모든 환경으로 이동 |
| 이 레포 한정 영구 규칙·합의 (기술스택·명명 등) | 레포 `CLAUDE.md` | ✅ git-tracked → 이동 |

**개인 세션**

| 사실의 종류 | 가야 할 곳 | 이동 여부 |
|---|---|---|
| 레포 범위 작업 선호·세션무관 학습 | 개인 per-project memory (`~/.claude/projects/<개인id>/memory`) | ⚠️ 정션 안 걸리면 machine-local → **이동 안 함** |
| 회사 컨텍스트 | — | ❌ 개인 세션에선 **기록 금지(분리 가드레일)** |

- 개인 레포 메모리에는 `claude-sync\memory`(회사 포함 공유 풀)로 **junction을 걸지 않는다** — 걸면 회사/개인이 한 폴더에 섞인다. 개인 레포의 영속 사실은 Drive 메모리가 아니라 **git-tracked 레포(`CLAUDE.md`/스냅샷)** 로 보내 휴대성과 분리를 동시에 만족시킨다.

**회사 세션**

| 사실의 종류 | 가야 할 곳 | 이동 여부 |
|---|---|---|
| 회사·동기화 대상 사실, 세션무관 학습 | `G:\내 드라이브\claude-sync\memory\` (회사 PC junction = `~/.claude/projects/<회사id>/memory`) | ✅ Drive로 모든 회사 PC 이동 |

- 회사 세션에서는 claude-sync/memory에 **기록 허용**(이게 회사 메모리 풀). frontmatter(`name` / `description` / `metadata.type` = user|feedback|project|reference)를 지키고 `MEMORY.md` 인덱스도 함께 갱신한다(폴더가 비어 있으면 첫 항목 추가 시 인덱스 생성).
- 단, **개인 컨텍스트**(개인 리모트·개인 Drive 폴더)는 회사 메모리에 **섞지 않는다.**
- **환경=PC 면 입력이 어디서 오든 메모리 기록이 가능하다** — 모바일에서 조종하고 있어도 같은 머신이라 junction 이 그대로 걸려 있다(클라우드 폴백의 "생성 전용" 제약 없음). 단 용도 라우팅은 §0에서 판별한 **요청 용도** 기준으로 한다.
- ⚠️ **junction 은 레포별 `<id>` 마다 따로 걸린다.** 새 레포에서 처음 종료하면 없을 수 있다 — 그때는 기록 전에 `작업시작` §3-PC-1 로 만든다.

- 핵심 규칙: **"다음 세션이 이어가는 데 필요"하면 반드시 git-tracked(스냅샷/CLAUDE.md)로.** per-project 메모리는 보조용이며, junction이 없으면 다른 환경에서 사라진다 — 이 점을 사용자에게 알린다.
- (참고: `.claude\commands` 와 글로벌 `~/.claude/CLAUDE.md` 는 정션·Drive 동기화 대상이 **아니다**. 커맨드의 정본은 전용 git 레포 **`claude-commands`** 이며, 글로벌 `~/.claude/commands`는 `sync-commands.ps1`로 복사된 사본이다.)

### 3-b) 메모리 git 백업 — 회사 세션·환경=PC 에서 **매번**   ← v2.6 신설

메모리를 고쳤든 안 고쳤든, 회사 세션이 §3 을 지나면 **여기서 백업을 돌린다.**

```powershell
pwsh "E:\claude-memory\scripts\memory-backup.ps1"
```

- **멱등이다** — 변경이 없으면 아무것도 하지 않는다. 그래서 "고쳤을 때만"이라는 조건을 두지 않는다. **조건이 붙으면 잊는다.**
- **왜 §3 직후인가** — 메모리를 방금 만진 자리이고, §4 커밋·푸시 **앞**이라 한 흐름으로 끝난다.
- **왜 필요한가** — claude-sync 3-레이어 중 **메모리만 사본이 하나였다.** 2026-08-22 에 Drive 메모리 53건이 통째로 휴지통에 들어갔고(forge `install.ps1` 이 junction 을 따라감 — `작업시작` §3-PC-1), 전량 복원했지만 **그건 운이었다.** `claude-memory` 레포가 그 이중화다.
- ⚠️ **정본은 Drive 다.** 이 레포는 스냅샷이자 안전망이지 정본이 아니다. **Drive 폴더에 `git init` 을 하지 않는다.**
- ⚠️ **스크립트가 `중단: 정본 폴더가 비어 있습니다` 로 멈추면 그것은 실패가 아니라 방어다** — Drive 동기화 문제이거나 파일이 휴지통에 갔다는 신호다. **재시도하지 말고** `%LOCALAPPDATA%\Google\DriveFS\...\metadata_sqlite_db` 의 `items.trashed` 를 확인한다(`[[memory-drive-incident-and-git-mirror]]`).
- **개인 세션·클라우드 폴백에서는 돌리지 않는다** — 개인 메모리는 이 풀에 들어가지 않고(§3 분리 가드레일), 클라우드에는 `G:`·PowerShell 이 없다.

## 4) 영속화 — 커밋 & 푸시 (용도별 리모트, 확인 후)

- 스냅샷 + 의미 있는 변경을 **커밋**하고 **용도에 맞는 리모트**로 **푸시**한다. 이 푸시가 곧 **다른 환경에서의 resume를 가능하게 하는 단계**다.
  - **개인**: `github.com/junesunghong/WebCrawler`(또는 해당 개인 레포) `main`.
  - **회사**: 현재 회사 레포의 `origin`(예 MailAgent), 현재 브랜치 또는 `main`.
- 푸시는 **외부로 나가는 동작 → 반드시 사용자에게 먼저 확인**한 뒤 실행한다. 커밋 메시지 제안: `작업 스냅샷: <주제> (다음 단계 N개)`.
  - **예외(체크포인트)**: §0-b의 완화 규칙 — 스냅샷+기존 추적 파일의 커밋·푸시는 사전 승인 동작. 새 파일 추가·대량 변경·강제 푸시는 원 규칙대로 확인.
- **클라우드(Web 폴백 — Claude Code on the web) 세션은 보통 `main` 직접 push가 아니라 새 브랜치 + PR(흔히 draft)로 전달**한다. 이때 스냅샷은 **PR 안에만** 있고 `main`엔 없어 — **PR을 머지하기 전까지 다른 환경(PC)의 `작업시작`이 직전 세션을 못 본다.** → 배너에 **PR 번호를 명시**하고, "다음 단계"에 **"PC에서 PR #N 머지(draft면 ready 전환 후)"** 를 넣는다. (환경=PC 끼리는 같은 머신이거나 main 직접 push라 해당 없음 — 입력이 PC 앞이든 모바일이든 마찬가지다.)
- `git remote -v`로 **용도와 리모트가 일치**하는지 재확인한다. **불일치 시(용도=개인인데 회사 리모트, 또는 반대) 멈추고 경고한다.**
  `data/`·`.env` 등은 `.gitignore`로 제외됨을 신뢰하되, `git status`에 **예상 못한 대용량·비밀 파일**이 보이면 경고하고 임의 수정하지 않는다.
- **(HARD-GATE) 스냅샷 전파 검증** — 커밋·푸시 후, 이번 스냅샷 파일이 **실제로 추적·푸시됐는지** 확인한다. 이 검증을 통과해야 종료(또는 체크포인트)가 성립한다(주장 금지·확인 필수, golden-principle #10 증거 기반).
  - 추적 확인: `git ls-files --error-unmatch _snapshot/<파일명>.md` (실패 = 미스테이징 → 스테이징·커밋 누락).
  - 푸시 확인: `git log origin/<branch> --oneline -- _snapshot/<파일명>.md`가 커밋을 반환해야 함(클라우드 폴백의 PR 경로는 PR 브랜치 기준).
  - **어느 하나라도 실패하면**: 배너 `푸시` 줄에 ⚠️ **"스냅샷 미전파 — 다른 환경에서 이어갈 수 없음"** 을 표기하고, 누락 원인(미커밋/미푸시/사용자 보류)을 적는다. 같은 머신에서만 이어갈 수 있음을 고지한다. **이 경고는 항상 답변 맨 앞에** 둔다 — 모바일에서 조종 중일 수 있고, 그러면 스크롤 아래에 묻혀 못 본다. (입력이 어디서 오는지는 판별할 수 없으므로 조건을 걸지 않는다.)
- per-project 메모리(3번)는 (junction이 없으면) git에 올라가지 않으므로 **"이 환경에만 남는다"** 고 명확히 고지한다.
- (드리프트 방지) 이 세션에서 `.claude/commands/`의 커맨드 또는 정본 레포를 수정했다면, 다음 단계에 **정본 반영**을 포함한다:
  `claude-commands` 레포에 커밋·푸시 후 `pwsh "<claude-commands>\scripts\sync-commands.ps1"`로 글로벌 갱신. 모바일에서 쓸 레포면 `pwsh "<claude-commands>\scripts\propagate.ps1"`로 해당 레포 `.claude/commands/`에 vendoring. **정본은 항상 `claude-commands` 레포다.** 환경=PC 면 별도 반영이 필요 없다 — 글로벌 사본이 곧 그 세션이 쓰는 커맨드다. ⚠️ **`propagate` 는 vendoring 까지만 하고 커밋은 사람 몫이다** — Monday 가 v2.4.0 을 디스크에만 갖고 있던 전례가 있다(2026-08-19 발견).

## 5) 마무리 가드레일 재점검 + 종료 배너

- 종료 직전 비혼합 가드레일을 한 번 더 확인한다:
  - **개인**: 개인 GitHub·개인 Drive만, 회사 컨텍스트 미참조.
  - **회사**: 회사 레포·claude-sync만, 개인 자격증명·드라이브 미혼합.
  - **머신=임시**: 로컬에 자격증명 영구저장 금지.
  - **요청 용도 ≠ 머신 용도**: 불일치가 있었다면 배너에 기록. 모바일에서 조종할 때 특히 섞이기 쉽다.
- 아래 형식으로 **무엇을 / 어디에 저장했는지**와 **다음 세션이 무엇을 이어갈지**를 보여준다.

```
🧭 작업 종료 요약   (체크포인트는 제목을 "체크포인트 요약"으로)
- 환경 : PC | 클라우드(Web 폴백)
- 머신 : 회사 PC | 집 PC | 클라우드
- 조종 : 미상 | 회사 | 집 | 이동 중        ← 근거 없으면 미상. 묻지 않는다
- 용도 : 개인 | 회사
- 레포 : <name> (<remote>, 브랜치 <branch>)
- 변경 : <커밋 N개 / 미커밋 M개>   테스트: 통과 | 실패 ⚠️ | 미확인 ⚠️
- 스냅샷 : _snapshot/<파일명>.md  (다음 단계 K개)  [추적·푸시 확인 ✅ | ⚠️ 미전파]
- 메모리 : 레포 CLAUDE.md <갱신/무> · <개인: per-project(이 PC 전용) | 회사: claude-sync/memory> <갱신/무>
- 백업 : claude-memory <커밋 N건 / 변경 없음 / 스킵(개인·클라우드)>   ← §3-b
- 푸시 : <remote>/<branch> 푸시 완료(스냅샷 포함 검증✅) | PR #N 생성(머지 필요) | 보류(확인 대기) | ⚠️ 스냅샷 미전파
- 가드레일 : <용도 기준 — 요약>
──
▶ 다음 세션 이어갈 일 : <스냅샷 "다음 단계" 최상위 1–2줄>
```

- ⚠️ **자리를 떠나며 종료했다면 세션 창은 남긴다** — 상주 서버가 없어 **PC 에 열린 세션에만 붙는다.** `/clear <머신>-<레포>` 로 이름을 붙여 두면 모바일 목록에서 알아볼 수 있다(`작업시작` §2 세션 이름 규칙). **나중에 모바일로 이어갈 생각이 없으면 신경 쓰지 않는다.**

미완·경고가 있으면 해당 줄에 ⚠️ 를 붙이고, 배너 하단에 한 줄 경고를 추가한다. **모바일 가독성을 항상 우선한다** — 배너는 그대로 두고 상세가 길면 요약한 뒤 근거를 파일 경로로 가리킨다. 지금 모바일에서 보고 있는지는 알 수 없으므로 조건을 걸지 않는다.

## 엣지케이스

- **`_snapshot/` 폴더 없음** → snapshot-archive 스킬이 생성(스킬 워크플로에 위임).
- **같은 날 스냅샷 다수** → `YYYY-MM-DD-HHMM_<slug>.md` 시간 suffix로 충돌 회피. "작업 시작"은 가장 최근 `*.md`를 읽으므로 정렬이 어긋나지 않게 한다. (`.ckpt.md`도 같은 정렬 규칙을 따른다.)
- **커밋할 것 없음 / 노이즈만**(`.vs/` 등 이미 ignore된 IDE 노이즈) → 커밋 생략, 배너에 "변경 없음". 추적 안 되는 새 노이즈가 보이면 `.gitignore` 추가를 **제안만** 하고 임의 수정하지 않는다.
- **테스트 실패 / 변경 후 미실행** → 종료를 막지 않되 스냅샷 "다음 단계"·"주의"에 명시하고 배너에 ⚠️.
- **미푸시 커밋이 이미 쌓여 있음** → `git log origin/main..HEAD`로 감지해 이번 스냅샷 커밋과 함께 일괄 푸시 대상에 포함.
- **푸시 실패 / 네트워크·리모트 권한(프록시 403)** → 로컬 커밋은 보존됨을 안내하고, **다른 환경에선 푸시 전까지 이동 불가**임을 경고. 같은 PC면 로컬 스냅샷으로 이어갈 수 있음.
- **스냅샷 생성됐으나 커밋 누락(orphan)** → §2에서 만든 스냅샷이 §4 커밋·푸시를 안 거쳐 **untracked로 방치**되는 경우(세션 중단·푸시 보류·첫 적용 실수 등). §4 HARD-GATE 검증(`git ls-files --error-unmatch`)이 이를 잡는다. 발견 시 ⚠️ "스냅샷 미전파"로 배너에 명시하고, 커밋·푸시를 마저 하거나(사용자 확인) 명시적으로 보류임을 고지한다. **검증 없이 "git-tracked" 단정 금지.** (실제 사례: 2026-06-22 회사PC 첫 적용 시 personalization 스냅샷이 orphan으로 남아 집PC로 미전파 — 메모리+PR 다중화로만 흡수됨.)
- **클라우드 폴백 세션(Claude Code on the web)** → 변경은 보통 **새 브랜치 + PR(draft)로 전달**된다(직접 `main` push 아님). 스냅샷 작성 후 "다음 단계"에 **"PC에서 PR #N 머지(draft면 ready 전환)"** 를 남긴다. 머지 전까지 PC `작업시작`은 직전을 `main`에서 못 보고 **열린 PR에서 찾아야** 한다(작업시작 §4).
- **용도와 리모트/드라이브 불일치**(개인 레포인데 회사 리모트가 잡힘, 또는 반대) → 4)·5)에서 멈추고 경고("작업 시작" 불일치 경고와 대칭).
- **회사 세션 첫 메모리 기록** → `claude-sync/memory`에 노트 생성 + `MEMORY.md` 인덱스 갱신(폴더 인덱스 없으면 생성).
- **회사 레포 복제 작업**(MailAgent 등에 이 워크플로 복제) → 분리 가드레일상 회사 사실은 **회사 세션에서만** claude-sync에. 개인 세션에선 스냅샷 "다음 단계"에 메모로만 남긴다.
- **체크포인트 누락** → 변경을 만들고 체크포인트 없이 방치하면 다른 환경이 이어갈 수 없다. **HARD-GATE 는 §4까지 도달한 세션만 검증하므로 중간에 멈춘 세션은 그물을 통과한다** — 실효 대책은 다음 `작업시작`의 **untracked 스냅샷 감지**다(작업시작 §4). 2026-08-10 에 스냅샷이 커밋 없이 3일간 갇힌 사례가 실제로 있었다.
- **동시 실행 충돌** → 이 머신의 세션들은 **같은 파일시스템**을 본다(VS Code 창 여러 개·모바일에서 조종하는 세션 전부). 같은 레포를 동시에 수정하면 커밋이 엉킨다. 규칙: **같은 레포는 한 번에 한 세션만.** 시작 시 미커밋 변경을 발견하면 경고하고 확인받는다(작업시작 §2 동시 작업 가드). ⚠️ 상주 서버가 없어진 뒤에도 이 위험은 그대로다 — 원인은 서버가 아니라 **머신이 하나**라는 사실이었다.

## 전제

- 이 절차는 **현재 세션에 해당 레포가 있어야** 동작한다.
- "작업 종료"는 상태를 **기록·영속화**할 뿐, 미완 작업을 대신 끝내지 않는다. 미완은 스냅샷 "다음 단계"로 넘긴다.

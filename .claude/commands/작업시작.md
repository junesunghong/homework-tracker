## 1) 네 가지 차원 확정   ← v3.1 개정 (「위치」를 「머신」·「조종」 둘로 갈랐다)

> **축이 셋이 아니라 넷이다** (케이스분석 §2). **머신**(세션이 도는 컴퓨터)·**조종**(사람이 어느 머신 앞에 있는가)·**환경**(PC/클라우드)·**용도**(회사/개인). 머신과 환경은 자동 판별되고, **조종은 자기신고 외에 수단이 없다.**
>
> `되묻기` 컬럼 = **사용자에게 되묻는 횟수**. `0` = 근거가 이미 있어 안 묻는다 / `1` = `AskUserQuestion` 을 한 번 띄운다.

1. **용도 (회사 / 개인)** — *자동 판별*
   - 현재 레포의 `CLAUDE.md`(없으면 도메인 단서)로 판별. 회사/MailAgent/Mirero/사내 → **회사**, "개인용/회사무관" → **개인**. 단서 없으면 질문.
   - ⚠️ **레포가 아직 안 정해졌으면(§2) 머신 기본값을 쓴다** — 회사 PC = **회사**. 레포 확정 후 다르면 그때 정정하고, 배너에 `(머신 기본값)` 이라고 근거를 적는다.
     *판별 근거가 "현재 레포의 `CLAUDE.md`" 인데 레포는 §2 에서 정해지므로 그대로 두면 순환이다. 이 한 줄이 순환을 끊는다.*
   - **요청 단위로 판별한다** — 머신은 한 대로 고정이지만 들어오는 요청의 용도는 매번 다를 수 있다. 요청마다 대상 레포·내용으로 용도를 다시 정한다(§4 가드레일과 연동).
2. **머신 (회사 PC / 집 PC / 클라우드)** — *승계 우선, 못 정할 때만 질문*   ← v3.1 개명 (구 「위치」)
   - **머신은 상수다.** 세션마다 물을 것이 아니라 받아 온다. 순서대로:

     | 순서 | 근거 | 되묻기 |
     |---|---|---|
     | ① | 사용자가 직전 메시지에서 이미 밝혔다 | 0 |
     | ② | 환경변수 `WORK_LOCATION` 또는 `.claude/machine.local.json` | 0 |
     | ③ | `$env:COMPUTERNAME` 이 **`DESKTOP-6I5V3A4`** → **회사 PC** | 0 |
     | ④ | 직전 스냅샷 `세션 컨텍스트` 의 머신을 **승계** (같은 머신이면 안 바뀐다) | 0 |
     | ⑤ | `AskUserQuestion` 으로 **한 번** 묻는다 | 1 |

   - ③ 의 이름이 안 맞는 머신(집 PC 등)은 ④ 나 ⑤ 로 떨어진다. 한 번 답을 받으면 그 세션 안에서는 다시 묻지 않는다.
   - 새 머신을 상용화하면 ③ 의 이름 목록에 추가한다 — 그게 이 질문을 영구히 없애는 방법이다.
   - ⚠️ **구판 스냅샷 호환** — 2026-08-25 이전 스냅샷 헤더는 `위치 …` 로 적혀 있다. **그대로 읽어 `머신` 에 넣는다.** 과거 헤더를 고치지 않는다.
3. **조종 (회사 / 집 / 이동 중 / 미상)** — *자기신고·승계만. **절대 묻지 않는다***   ← v3.1 신설

   | 순서 | 근거 | 되묻기 |
   |---|---|---|
   | ① | 사용자가 말했다 (*"집에서 하는 중"*) → **그 세션 동안 유지** | 0 |
   | ② | 직전 스냅샷 `세션 컨텍스트` 헤더에서 승계 | 0 |
   | ③ | 근거가 없으면 **`미상`** | 0 |

   - ⚠️ **`미상` 을 기본값으로 두는 것이 이 축의 핵심이다.** 필수로 만들면 질문이 부활하고, 그러면 v3.0 이 없앤 되묻기가 되살아나 개정이 무의미해진다.
   - **`조종` 이 `집` 또는 `이동 중` 일 때만** 배너에 제약 경고를 붙인다:

     ```
     ⚠️ 원격 조종 중 — 재부팅·전원·USB 등 물리 조작 불가.
        세션 창을 닫으면 모바일에서 새로 만들 수 없습니다(상주 서버 없음).
     ```

   - **`미상` 이거나 머신과 같으면 경고를 붙이지 않는다.** 케이스 1(회사 PC 앞·평일 근무)이 빈도 최상인데 거기서 배너가 길어지면 안 된다.
   - **왜 판별 안 되는 축을 배너에 두는가** — v3.0 은 *"입력 위치는 절차가 안 갈린다"* 고 단정했으나 **그건 과했다.** 아래 세 줄이 머신이 아니라 **사람**으로 갈린다 (케이스분석 §3 실측):

     | 제약 | 조종=머신 앞 | 조종=집·이동 중 |
     |---|:-:|:-:|
     | **재부팅·전원** (끊기면 되살릴 손이 없다) | ✅ | ❌ |
     | **USB·프린터·모니터** 물리 조작 | ✅ | ❌ |
     | **새 세션 생성** (열린 창에만 붙는다) | ✅ | ❌ |

     2026-08-22 이 상태(집에서 회사 PC 조종)에서 **재부팅이 필요한 작업을 제안했다면 월요일까지 복구 불가**였다. 도중에 알아챘지만 **배너가 아니라 세션의 판단에 의존**했다.
4. **환경 (PC / 클라우드-Web 폴백)** — *자동 판별*   ← v3.0 재정의

   | 값 | 판별 | 뜻 |
   |---|---|---|
   | **PC** | Windows · `G:` 드라이브 · PowerShell 있음 | 이 머신에서 실행된다. 파일·시크릿·MCP·메모리 junction·규칙 전부 있음 |
   | **클라우드(Web 폴백)** | 리눅스 컨테이너 · `G:`·junction·PowerShell 없음 | Claude Code on the web. 로컬 파일·메모리·시크릿·규칙 없음 |

   ⚠️ **`PC(Local)` / `PC(Remote Control)` 구분은 폐기했다** (v3.0). 환경 층(`remoteControlAtStartup=true`)이 켜진 뒤로 **PC 의 모든 세션이 RC 로 뜬다** — 즉 Local/RC 는 세션의 상태가 아니라 **입력이 PC 앞에서 오는지 모바일에서 오는지**의 차이뿐이고, 같은 머신·같은 세션이라 **절차가 갈리지 않는다.** 게다가 그 입력 위치는 **자동 판별이 불가능하다**(실측 — 메모리 `[[work-dashboard]]`). **구분할 수 없고, 구분해도 할 일이 같은 축은 배너에 두지 않는다.**

> **세션은 휘발성, git이 단일 진실원.** 세션 목록은 **기기별·비동기**라 이어감의 주체가 아니다.
> - **주력 = PC** — 무거운 구현·시크릿·**메모리 노트 편집/`MEMORY.md` 인덱스 정리**(Web의 Drive MCP는 생성 전용 → 편집·삭제 불가)·푸시. 모바일에서 조종하든 PC 앞에 앉아 있든 **같은 세션**이다.
> - **폴백 = Web** — PC 가 꺼져 있거나 닿지 않을 때의 유일한 수단으로 **폐기하지 않고 유지**한다. 읽기·가벼운 메모·스냅샷 작성.
>
> 어느 세션에서 열든 `git pull` + 이 명령이 최신 스냅샷의 `세션 컨텍스트`를 읽어 이어준다.

## 2) 레포 확정 — cwd 가 먼저 정한다   ← v3.0 신설

**환경 층이 켜지고 상주 서버가 중단된 뒤로 세션은 작업 폴더에서 열린다**(RC 브리지는 손 안 대도 붙는다). 그래서 대부분의 세션은 **이미 레포에 뿌리내린 상태로 시작**한다 — 아래 결정 순서를 돌릴 일이 없다.

| cwd 상태 | 판정 | 할 것 |
|---|---|---|
| **git 레포 안** | `git rev-parse --show-toplevel` 성공 | **그 최상위가 레포다.** ①~③ 을 돌리지 않는다. 배너 `레포` 줄에 `(cwd)` 로 적는다 |
| **git 밖** (`E:\` 루트 등) | 실패 | 아래 ①~③ |

### ⭐ 두 세션의 역할은 갈라져 있다 — 편의가 아니라 **원칙**이다   ← v3.3 신설

| | **`E:\` 루트 세션** | **레포별 세션** |
|---|---|---|
| **용도** | **새 레포가 필요한 작업**의 진입점 | 진행 중인 레포 작업 **전부** |
| **왜 필요한가** | 폴더가 아직 없으니 **거기서 세션을 열 수가 없다.** 그리고 상주 서버가 없어 **모바일에서 세션을 새로 못 만든다** → 원격에서 새 레포 작업을 시작하려면 **이 세션이 열려 있어야** 한다 | `cwd` 가 레포를 정한다 |
| **빈도** | 낮다 (새 레포는 자주 안 만든다) | 대부분 |

⛔ **`E:\` 하위의 진행 중인 레포 작업을 루트 세션에서 하지 않는다.** 그 레포 폴더에서 **각자 세션을 연다.** 루트 세션이 편해 보여도(권한 규칙이 더 많다) 그 이유로 끌어오지 않는다.

⚠️ **권한 규칙이 레포 세션에서 줄어드는 것은 「루트에서 하라」는 근거가 아니라 「그 레포 규칙을 채우라」는 신호다.** 허용목록은 **가산이 아니라 cwd 기준**이라(아래 절) 레포 세션은 `E:\.claude\` 를 못 받는다. 실측(2026-08-25): `E:\` 루트 **80개** vs `WorkSession` **49개**. **그 31개 차이는 결함이지 설계가 아니다** — 자주 쓰는 것(`Read(~/.claude/**)`·`pnpm test *`·`git -C $r fetch` 등)을 그 레포 `.claude/settings.local.json` 에 옮겨 담는다.

### 미바인딩일 때의 결정 순서 — 3단계, 되묻기 0   ← v3.1 개정 (5단계 → 3단계)

| 순서 | 근거 | 결과 | 되묻기 |
|---|---|---|---|
| ① | 메시지에 명시 (`작업시작 WorkSession`) | 즉시 확정 | 0 |
| ② | 이 대화에서 이미 정한 레포 | 승계 | 0 |
| ③ | **기본값 `WorkSession`** | 잠정 확정 — ① 이 언제든 덮어쓴다 | **0** |

배너 `레포` 줄에 **어느 경로로 정했는지** 표시한다(예: `MailAgent (cwd)` · `WorkSession (루트 세션 기본값)`).

- ⛔ **v3.0 의 ③「최신 스냅샷 제시」·④「후보 목록 선택」을 삭제했다.** 그 둘은 **서버 모드 잔재**다 — 상주 서버가 `E:\` 루트에 뿌리내려 **모든 세션이 루트에서 뜨던 시절**에는 요청마다 레포를 골라야 했다. 지금은 진행 중인 레포 작업이 애초에 루트로 오지 않으므로(위 절) **고를 후보가 없다.**
- **그리고 그 둘은 문서를 자기모순으로 만들고 있었다** — §2 는 "③④를 돌려라"(되묻기 발생) 하는데 §5 배너는 "**비워 두지 않는다** — 안 정해지면 기본값"이라고 한다. 그대로 따르면 **되묻기가 먼저 나온다.** 2026-08-25 세션이 실제로 ③ 에 걸려 `AskUserQuestion` 을 띄웠고 사용자가 끊었다.
- ⭐ **③ 을 둔 이유 — 루트 세션은 「레포가 아직 없는 작업」을 하러 온다.** 새 레포를 만들 작업이면 그 레포는 **아직 존재하지 않아** ①②로 정해질 수 없고, 새 레포 작업이 아니면 애초에 **여기 올 일이 없다.** 그 사이에도 **스냅샷을 쓸 곳과 푸시할 origin 은 있어야 한다** — 2026-08-19 에 루트 세션이 git 밖 폴더(`D:\Work\...`)를 작업해 **스냅샷이 한 건도 남지 않은** 사례가 그 모양이다.
- **왜 `WorkSession` 인가** — 새 레포 작업은 **자주 없다.** 그동안 루트 세션의 기록이 갈 곳이 필요하고, 그 레포가 작업체계·설정의 정본이라 **가장 가까운 귀속지**다(README 가 스스로를 *"작업체계 설계·운영 자산"* 이라 정의). **"루트 세션 = 메타작업" 이라서가 아니다** — 메타작업도 그 레포가 정해져 있으면 그 폴더에서 연다.
- **③ 은 잠정이다.** 새 레포가 정해지는 순간 ① 이 덮어쓴다. 옮길 때는 `작업종료` §0-b 트리거 4번(미커밋 변경이 있으면 체크포인트 확인)을 따른다.
- ⚠️ **루트 세션은 닫지 않는다.** 상주 서버가 없어 **모바일에서 세션을 새로 못 만들므로**, 원격에서 새 레포 작업을 시작할 진입점은 **열려 있는 이 세션 하나뿐**이다. `/clear 회사-E` 로 이름을 붙여 둔다(아래 세션 이름 규칙).
- ⚠️ **`E:\` 자체를 레포로 만드는 길은 검토 후 버렸다**(2026-08-20 실측). ⓐ 시크릿 4건이 repo 밖에 맨몸으로 있어 `git add -A` 한 번에 스테이징된다(`DM팀-운영시스템\AIDevFlow`·`Album`·`Event\frontend`·`DM팀-프로젝트\Monitoring` 의 `.env`) ⓑ 드라이브 8.6 GB·중첩 repo 10개(gitlink 로 들어가 이력이 무의미해진다) ⓒ `E:\.claude\settings.json` 은 **의도적으로 git 밖**이다 ⓓ 무엇보다 **루트에 버전관리할 고유 자산이 0개다** — 런처 5개는 `WorkSession\5_대시보드\launcher\` 의 사본이고 설정은 `claude-commands\settings\` 에 참고본이 있다.

### 레포 세션이면 그 레포의 권한 규칙이 걸린다 — 다만 항상 이득은 아니다

허용목록은 **cwd** 로 정해진다 (2026-08-21 실측):

| 설정 소스 | 기준 디렉터리 |
|---|---|
| `.claude/settings.json` (project) | **`cwd` 정확히** — 상위 폴더를 타고 올라가지 않는다 |
| `.claude/settings.local.json` (local) | **git 루트** (+ cwd 가 git 루트와 다르면 cwd 것도 함께) |
| `~/.claude/settings*.json` (user) | 홈 — **모든 세션** |

⚠️ **가산이 아니다.** 레포 세션은 `E:\.claude\` 의 루트 규칙을 **받지 않는다.** 규칙을 쌓아 두지 않은 레포에서 세션을 열면 루트 세션 때보다 **규칙이 줄어든다.** 실측 표·대책은 이용 가이드 §1-b 와 메모리 `[[claude-settings-permission-scope]]`.

### 세션 이름 규칙   ← v3.1 신설

`/clear <이름>` 의 이름은 **모바일 `Code` 탭에서 어느 세션에 붙을지 고르는 라벨**이다. 따라서 **머신을 가리켜야 한다.**

> **`<머신>-<레포 또는 E>`** — 예 `회사-E` · `회사-MailAgent` · `집-E`

⚠️ **사람 위치(조종)는 이름에 넣지 않는다.** 이름은 머신에 붙고 사람은 옮겨 다닌다. 넣으면 집에서 조종할 때마다 이름이 거짓이 된다.

*발단: 2026-08-22 에 `/clear 집-E` 와 `/clear 회사-E` 가 같은 대화에서 연달아 나와 어느 쪽이 지금인지 흐려졌다. 둘 다 규칙상 맞는 이름이었는데 **규칙이 어디에도 안 적혀 있었다.***

### 동시 작업 가드

시작 시 대상 레포에 미커밋 변경(`git status -s`)이 있으면 **작업을 시작하지 말고** "다른 세션이 이 레포를 작업 중일 수 있습니다 — 진행할까요?" 를 먼저 묻는다. 승인 전에는 읽기만 한다. **같은 레포는 한 번에 한 세션만**이다.

## 3) 이어가기 복구 (환경별 — 핵심)

확정된 환경에 맞춰 아래를 **점검하고, 빠진 것만 복구**한다. (이미 갖춰졌으면 건너뛴다.)

### ⭐ PC 라면 — 먼저 이 한 줄로 전부 수집한다   ← v3.2 신설

```powershell
pwsh "E:\claude-commands\scripts\start-scan.ps1"
```

**§1 머신·환경 · §2 레포 확정 · §3 복구 점검 · §5 배너 데이터를 한 번에 낸다.** 아래 항목들을 손으로 하나씩 확인하지 않는다.

| 출력 키 | 채우는 곳 |
|---|---|
| `COMPUTERNAME` · `MACHINE` | §1-2 머신 (`COMPANY`→회사 PC · `UNKNOWN`→④⑤로) |
| `ENV` · `DRIVE_G` | §1-4 환경 |
| `REPO` · `REPO_VIA` · `REMOTE` · `BRANCH` · `SYNC` | §2 레포 · §5 `레포` 줄 (`UNBOUND` 이면 §2 ①~③) |
| `SNAPSHOT` · `STATE` · `SNAP_HEADER` | §5 `상태` · `직전` 줄 |
| `UNMERGED` | §5 `미머지` 줄 |
| `UNTRACKED_SNAP` | §5 untracked 감지 |
| `JUNCTION` · `MEMORY_FILES` | §3-PC-1 |
| `CMD_SYNC` | §3-PC-5 (해시 대조) |

- **`SYNC` 가 `behind N`** 이면 그때만 `git pull`. **`JUNCTION` 이 `MISSING`** 이면 그때만 §3-PC-1 생성. **`CMD_SYNC` 가 `2/2 match` 가 아니면** 그때만 §3-PC-5. **전부 정상이면 추가 호출이 없다.**
- 스크립트가 없거나(구 clone) 환경이 클라우드면 아래 절차를 손으로 한다.
- ⚠️ **이 스크립트는 현재 레포만 본다.** 그게 설계다 — 아래 「범위」 절 참조.

### 공통 — 메모리 먼저 로드
- 직전 작업 맥락은 메모리에 있다. 환경에 맞게 반드시 먼저 적재한다.

### PC (Windows + G:) — 스크립트가 없을 때의 수동 절차
1. **메모리 junction** — `~/.claude/projects/<id>/memory` 가 `G:\내 드라이브\claude-sync\memory` 로 연결돼 있는지 확인.
   - `<id>`=작업 디렉터리에서 파생(예 `e:\DM팀-업무자동화\MailAgent` → `e--DM--------MailAgent`).
   - 없으면 생성: `New-Item -ItemType Junction -Path $mem -Target $dst`.
     ⚠️ `memory`가 실폴더로 이미 있으면 백업 후 교체하되, **`Remove-Item -Recurse -Force`는 도구 안전가드에 막힘** → 수동 백업/이동으로 처리하거나 사용자에게 안내.
   - 연결되면 다음 세션부터 메모리가 자동 로드된다.
   - ⚠️ **`<id>` 는 레포마다 다르다** → 새 레포에서 처음 세션을 열면 junction 이 없다. 레포별 세션을 쓰는 지금은 이 점검이 전보다 자주 걸린다.
   - 🔴 **이 junction 은 `~/.claude/` 를 통째로 옮기는 스크립트에 취약하다.** forge `install.ps1` 의 `Move-Item $ClaudeDir` 이 junction 을 **따라 들어가** 2026-08-22 에 Drive 메모리 **53건이 휴지통으로 이동**했다(전량 복원, 손실 0). junction 은 링크가 아니라 **폴더처럼 보이기 때문**이다.
     - **`/forge-update` 나 `install.ps1` 을 돌리기 전에 junction 을 먼저 끊는다.** 끝나면 다시 만든다.
     - 회사 PC 에 같은 junction 이 **13개** 있다(2026-08-25 실측 — 전부 `G:\내 드라이브\claude-sync\memory` 를 가리킨다). 하나만 끊어서는 소용없다:
       ```powershell
       Get-ChildItem "$HOME\.claude\projects" -Directory |
         ForEach-Object { Get-Item (Join-Path $_.FullName 'memory') -Force -EA SilentlyContinue } |
         Where-Object LinkType -eq 'Junction' | Select-Object FullName, Target
       ```
     - ⚠️ **진단은 로컬 `ls` 로 안 된다** — Drive MCP 검색도 `G:` 마운트도 **휴지통 파일을 제외**해 둘 다 "0개"로 보고한다. 판정 경로는 `%LOCALAPPDATA%\Google\DriveFS\...\metadata_sqlite_db` 의 `items.trashed` 뿐이다.
     - 상세·복구 절차: 메모리 `[[memory-drive-incident-and-git-mirror]]`. 이중화 대책은 `E:\claude-memory` 레포(`작업종료` §3 이 백업을 돌린다).
2. **코드 최신화** — 현재 레포에서 `git fetch` 후 뒤처졌으면 `git pull`.
   - fetch 직후 **`git branch -r --no-merged origin/main`로 미머지 원격 브랜치를 확인**한다 — PR 없이 푸시된 실험/병렬 작업(예 `experiment/*`)을 §5 배너 `미머지` 줄에 보고하기 위함. (main·PR만 보면 놓친다.)
   - ⛔ **`pull-all.ps1`(전 레포 일괄 pull)은 시작 절차에 넣지 않는다.** 이 세션이 쓸 레포는 하나이고, 나머지는 그 레포에서 세션을 열 때 각자 당기면 된다. 여러 대를 오간 뒤 한꺼번에 맞추고 싶을 때 **손으로** 돌린다: `pwsh "G:\내 드라이브\claude-sync\scripts\pull-all.ps1"`
3. **시크릿** — `.env` 없거나 키 부족하면 `pwsh "G:\내 드라이브\claude-sync\scripts\secrets-restore.ps1" -Path "<레포>"`. (없는 신규 키는 생성 후 `secrets-backup.ps1`로 Drive 동기화)
4. **런타임**(실행이 필요할 때만) — `pnpm install`(네이티브 모듈 포함), 로컬 LLM 쓰면 Ollama 구동·모델(`ollama list`) 확인·필요시 `ollama pull`.
5. **커맨드 동기화**(전용 정본 레포) — 글로벌 `~/.claude/commands/작업시작.md`·`작업종료.md`가 없거나 오래됐으면 정본을 최신화해 복사:
   `git -C "<claude-commands 경로>" pull; pwsh "<claude-commands 경로>\scripts\sync-commands.ps1"`.
   - 정본 레포가 `E:\` 하위면 `pull-all.ps1`로도 갱신되고, 복사만 다시 돌리면 된다. 이 점검이 회사 PC에서 `/작업시작`이 사라지는 문제를 막는다.
   - **판정은 해시로 한다** — `sha256sum` 으로 글로벌 사본과 정본을 대조하면 "오래됐는지"를 추측하지 않는다.

> ⚠️ **v2.4 의 6번(RC 서버 상태 점검)은 v3.0 에서 제거했다.** 상주 서버는 2026-08-21 중단됐고 모바일 경로는 **환경 층**(`remoteControlAtStartup`)이 담당한다 — 서버 상태를 찍으면 매 세션 `미기동` 을 경고로 보고하는데 **그건 정상 상태**여서 정보량이 0이다. 서버를 되살릴 때의 절차·진단은 이용 가이드 §2 에 보존돼 있다.

### 클라우드 / Web (컨테이너 — G:·junction·PowerShell 없음) — 폴백 경로
> **주 경로는 PC** 다. 이 절은 **PC 가 꺼져 있거나 닿지 않을 때의 폴백**으로 유지한다.
1. **메모리** — Google Drive MCP `read_file_content`로 `MEMORY.md`(ID `1cle8foAr2lzUpQxMQrGIboD5LzQXeqkX`) 읽고, 관련 노트도 같은 방식으로 적재. (로컬 `~/.claude`엔 메모리가 없어 자동 로드 안 됨)
2. **코드** — 보통 레포가 이미 clone됨. `git fetch`로 브랜치/최신 여부 확인, 필요시 `pull`/`checkout`. 없으면 사용자에게 레포 열기 요청.
3. **시크릿** — 필요시 Drive MCP로 `claude-sync/secrets/.../.env` 참조(복원 스크립트는 Windows 전용 → 수동 참조).
4. **커맨드** — 여기서는 글로벌 `~/.claude/commands`를 못 쓰므로, **연 레포의 `.claude/commands/`에서만** 슬래시 명령이 잡힌다. 정본 레포(`claude-commands`) 또는 `propagate.ps1`로 vendoring된 레포를 열어야 `/작업시작`·`/작업종료`가 동작한다.
5. ⚠️ Drive MCP는 **생성 전용**(제자리 수정·삭제 불가) → 기존 메모리/인덱스 편집은 **PC 세션**에서.
6. ⚠️ **글로벌 규칙(rules)이 걸리지 않는다** — 규칙은 vendoring 대상이 아니다. 문서 개정처럼 규칙에 의존하는 작업은 여기서 하지 말고 PC 에서 한다.

## 4) 환경 정합성 점검 (용도 기준)

- **개인**: 개인 리모트/브랜치(`git remote -v`)·개인 드라이브만. 회사(MailAgent/Mirero/gw.mirero/사내 자격증명·URL) 미참조.
- **회사**: 회사 레포/리소스만. 개인 자격증명·드라이브 미혼합.
- **머신=기타(임시/공용)**: 자격증명 로컬 영구저장 금지. 작업물은 git/Drive로만 보존, 로컬 흔적 최소화.
- **머신 용도 ≠ 요청 용도**에 주의 — 회사망 PC 에서 개인 작업 요청을 처리하면 개인 리소스가 회사 머신·회사망을 경유한다. 요청 용도가 머신 용도와 다르면 **실행 전에 경고하고 확인**받는다. 모바일에서 조종할 때 특히 섞이기 쉽다 — **실행은 언제나 그 PC 에서 일어난다.**
- 불일치(예: 용도=개인인데 회사 리모트/드라이브) → **작업 전 경고**하고 확인.

## 5) 요약 출력 + 이어가기 제안

### ⛔ 범위 — 배너는 **현재 레포만** 본다   ← v3.2 신설

**`직전`·`상태`·`미머지`·`untracked`·`이어갈 거리` 는 전부 §2 에서 확정한 그 레포 하나의 사실이다.** 다른 레포를 열어 보지 않고, **다른 레포의 일을 제안하지도 않는다.**

- **`E:\` 전체 조망은 이 커맨드의 일이 아니다** — `pwsh "E:\DM팀-업무자동화\WorkSession\5_대시보드\dashboard.ps1"` 이 그 일을 한다. 배너가 그걸 겸하면 **중복**이고, 레포 12개를 훑느라 시작이 느려진다.
- **레포가 `WorkSession (루트 세션 기본값)` 이어도 마찬가지다** — 그 레포 하나만 본다.
- 다른 레포의 미종료·미머지가 궁금하면 **대시보드를 안내**하고 넘어간다. 직접 훑지 않는다.

⛔ **「이어갈 거리」도 범위 안이다 — 다른 레포·다른 폴더의 일을 제안하지 마라.**   ← v3.3 추가

v3.2 는 제안에 **깊이 제한**(*"조사하지 마라"*)만 걸었고 **범위 제한**을 안 걸었다. 그래서 **조사 없이도 범위를 벗어날 수 있다** — 이미 로드된 메모리에 남의 프로젝트 일정이 있으면 그걸 그대로 제안에 올리게 된다.

| 제안해도 되는 것 | 제안하면 안 되는 것 |
|---|---|
| 현재 레포 스냅샷의 「다음 단계」 | **다른 레포의 다음 단계** |
| 현재 레포의 `미머지` 브랜치 | 다른 레포의 미머지 |
| 현재 레포에 관한 메모리 노트 | **`E:\` 밖 폴더의 일** (`D:\Work\...` 등) |

- **메모리에 다른 프로젝트의 급한 일정이 보여도 배너에 올리지 않는다.** 그 일은 **그 폴더에서 세션을 열 때 그 폴더의 기록이 알려 준다.** 각 작업은 자기 기록처를 갖고 있다.
- 정말 알려야 할 만큼 급하면 **배너 밖에서 한 줄로 언급**하고 넘어간다 — `이어갈 거리` **항목에 넣지 않는다.** 그 항목은 *"이 세션에서 지금 할 일"* 이지 *"세상에서 제일 급한 일"* 이 아니다.

⚠️ **실사례 (2026-08-26)** — 이 세션(레포 `WorkSession`)이 `D:\Work\...\기술부채` 의 A-DMS 회의를 **「다음 단계」 최우선**으로 올렸고, 종료 스냅샷에까지 적었다. 그러면 **다음에 `WorkSession` 을 여는 사람에게 "A-DMS 부터 하라"가 뜬다** — 작업체계 레포가 남의 프로젝트 일정을 들고 있는 꼴이고, *"각 레포 일은 각자 세션"* 원칙을 **스냅샷이 깨뜨린다.**

> **왜 못 박는가** — 2026-08-25 실측: 배너까지 **도구호출 25회 / 5분 57초**. 그중 **7회가 전 레포 훑기**였고, 같은 조건에서 다른 세션은 8회로 끝냈다. **3배 편차의 원인은 범위를 안 정해 준 것**이다. v3.0 이 레포를 `cwd` 하나로 좁혔는데 배너 항목에는 "어느 레포인지"가 안 적혀 있었다.

```
🧭 작업 컨텍스트
- 환경 : PC | 클라우드(Web 폴백)
- 머신 : 회사 PC | 집 PC | 클라우드   (상수 — 승계 우선, §1-2)
- 조종 : 미상 | 회사 | 집 | 이동 중   (자기신고·승계만 — 묻지 않는다, §1-3)
- 용도 : 개인 | 회사   (요청 단위 판별. 레포 미확정이면 머신 기본값)
- 직전 : <머신>·<환경> (<시각>) | (첫 세션)   ← 최신 스냅샷 `세션 컨텍스트`에서
- 상태 : 닫힘 | ⚠️ 열림(미종료 — <시각> 체크포인트 이후)   ← 최신 스냅샷 파일명으로 판정
- 레포 : <name> (<remote>, 브랜치 <branch>, 동기 <ok/뒤처짐>) [cwd | ①~③ 중 어느 경로]
         ※ **비워 두지 않는다.** 미바인딩이면 §2 ③ 으로 `WorkSession (루트 세션 기본값)` — 되묻지 않는다
- 미머지 : <브랜치/PR 목록 + ahead 커밋수> | 없음   ← 열린 PR + `git branch -r --no-merged origin/main` (PR 없는 실험/병렬 브랜치 포함)
- 복구 : 메모리<로드됨/MCP> · 시크릿<있음/복원> · 런타임<준비/스킵> · 커맨드<글로벌 있음/복사>
- 가드레일 : <적용 규칙>
```

- ⚠️ **`조종` 이 `집`·`이동 중` 이면** 배너 아래에 §1-3 의 제약 경고를 붙인다. **`미상` 이거나 머신 앞이면 붙이지 않는다** — 빈도 최상인 경우에서 배너가 길어지면 안 된다.
- **직전 세션 컨텍스트 확인**: 최신 `_snapshot/*.md`의 `세션 컨텍스트` 헤더(머신·조종·환경·용도·시각)를 읽어 **"직전 작업은 <머신>·<환경>에서 진행됨"**을 배너 `직전` 줄에 보고한다. 환경을 바꿔 와도(회사↔집·PC↔클라우드) 직전이 어디였는지 알 수 있다.
  - **구판 헤더(`위치 …`)는 그대로 읽어 `머신` 에 넣는다.** 2026-08-25 이전 스냅샷에는 `조종` 이 없다 — 그때는 `미상` 이다.
  - ⚠️ **직전이 클라우드(Web 폴백)였다면** 그 스냅샷이 `main`이 아니라 **미머지 PR**에 있을 수 있다 (Claude Code on the web은 main 직접 push가 아니라 **브랜치 + PR(흔히 draft)로 전달**). 스캔의 `SNAPSHOT` 이 예상보다 오래됐고 `UNMERGED` 에 브랜치가 있을 때 **그때만** `gh pr list` 를 돌려 **"직전이 PR #N에 있음 → 머지해야 이어짐"**을 알린다.
    - **조건 없이 `gh pr list` 를 돌리지 않는다.** `UNMERGED` 가 `none` 이면 볼 PR 도 없다.
  - **직전이 PC 였다면** `main`에 직접 푸시되므로 PR 확인은 불필요하다. 단 파일명이 `*.ckpt.md`면 "체크포인트에서 이어감(작업 열림)"으로 보고한다.
  - ⚠️ **직전 스냅샷이 커밋조차 안 돼 있을 수 있다.** `git status -s`에 `?? _snapshot/...`이 보이면 그 작업은 **이 머신에 갇혀 있다.** HARD-GATE는 §4까지 도달한 세션만 검증하므로 중간에 멈춘 세션은 그물을 통과한다 — **untracked 스냅샷 감지가 실효 대책이다.** 발견 즉시 배너에 올리고 커밋·푸시를 제안한다.
- **작업 상태 판정 + 미종료 감지** — 해당 레포 `_snapshot/`의 **최신 파일 확장자**가 곧 상태다. 별도 상태 파일을 두지 않는다.

  | 최신 스냅샷 | 상태 | 뜻 |
  |---|---|---|
  | `*.ckpt.md` | **열림** | 체크포인트만 하고 `작업종료`를 하지 않음 |
  | `*.md` (일반) | **닫힘** | 정상 종료됨 |

  - **상태는 레포 단위다.** 전역 상태가 아니다(스냅샷이 각 레포에 있으므로).
  - **열림인데 같은 레포로 시작** → 이건 "새 시작"이 아니라 **재개**다. **기본값은 "이어서 진행"**이고, 종료를 강요하지 않는다. 다만 아래 안내는 한 번 띄운다.
  - **열림인데 다른 레포로 시작** → 새 레포로 정상 진행하되, 배너에 **"<레포A>가 미종료 상태"**를 함께 고지해 잊히지 않게 한다.
  - **안내 문구는 "세션을 닫아라"가 아니라 "메모리가 낡는다"로 쓴다.** 체크포인트를 했으면 **코드는 이미 `main`에 있다.** 빠진 것은 `작업종료` §3 **메모리 반영**뿐이고, 그것이 안 되면 다음 작업시작이 **낡은 메모리를 근거로 판단**한다. 틀린 메모리는 없는 메모리보다 나쁘다.

    ```
    ⚠️ <레포>는 <시각> 체크포인트 이후 종료되지 않았습니다.
       코드는 이미 main에 있지만 메모리 반영이 안 됐습니다 — 다음 판단이 낡은 정보를 씁니다.
       ① 먼저 종료(메모리 반영) 후 시작   ② 그냥 이어서 진행   ③ 지금은 넘어가기
    ```

  - **차단하지 않는다.** 권고이고, 사용자가 ②·③을 고르면 그대로 진행한다.
  - ⚠️ **PR 없이 푸시된 미머지 브랜치(병렬·실험 작업)도 반드시 열거한다.** 열린 PR만 보면 **PR 없이 origin에 직접 푸시된 experiment/feature 브랜치**(예: `experiment/genspark-llm`)를 통째로 놓친다.
    - **§3 스캔의 `UNMERGED` 줄을 그대로 적는다.** 그것이 `git branch -r --no-merged` 결과다. **브랜치별로 더 파지 않는다** — ahead 커밋수·커밋 제목·그 브랜치의 스냅샷은 브랜치 하나마다 호출이 2~3회씩 붙고, **배너는 "있다"까지만 알리면 된다.**
    - 팀장님이 그 브랜치를 고르시면 그때 `git log --oneline origin/main..<branch>` 로 판다.
    - 메모리 프로젝트 노트의 실험/브랜치 항목(예 `[[mailagent-project]]`)과 **이미 로드된 범위에서** 교차 확인한다.
- **이어갈 거리 제안 — ⛔ 조사하지 않는다**   ← v3.2 개정

  **이미 손에 있는 것만으로 1~3개를 적는다.** 근거는 셋뿐이다:

  | 근거 | 어디서 | 추가 호출 |
  |---|---|:-:|
  | 현재 레포 최신 스냅샷의 **「다음 단계」 절** | §3 스캔의 `SNAPSHOT` 이 파일명을 줬다 → **그 절만** 읽는다 | **1회** |
  | 메모리 프로젝트 노트의 "상태/다음 단계" | **이미 로드돼 있다** | 0 |
  | `미머지` 줄 (스캔 출력) | 이미 있다 | 0 |

  「다음 단계」 절만 떼는 명령 (파일 전체를 읽지 않는다):

  ```bash
  awk '/^#+ .*다음 단계/{f=1;print;next} f&&/^#{2} /{exit} f' "_snapshot/<SNAPSHOT>"
  ```

  ⚠️ 종료 패턴이 `/^#{2} /`(`## ` 정확히)여야 한다. `/^## /` 로 쓰면 **제목 줄 자신이 매칭돼 한 줄만 나온다.**

  ⛔ **제안하려고 새로 파고들지 마라.** 대상 폴더를 열거나·문서를 읽거나·다른 경로를 확인하는 것은 **제안이 아니라 조사**다. **팀장님이 고르신 뒤에** 그 항목만 판다.

  - 제안은 *"무엇부터 할지"* 고르는 것이지 *"그것을 다 파악하는 것"* 이 아니다. 근거가 얕으면 **얕은 채로 제시**하고 "자세한 건 고르시면 확인하겠습니다"라고 적는다.
  - 메모리가 다른 폴더(예 `D:\Work\...`)를 가리켜도 **그 폴더를 열지 않는다.** 메모리에 적힌 것까지만 옮겨 적는다 — 메모리는 그러라고 있는 것이다.
  - 미머지 브랜치가 있으면 제안에서 빠뜨리지 않는다(스캔이 이미 알려 줬다).

  > **왜 못 박는가** — 2026-08-25 실측에서 **제안이 25회 중 13회(52%)** 를 먹었다. 메모리가 D-1 회의를 가리키자 `D:\Work\...` 문서 7개를 열었다. 그건 제안 단계가 할 일이 아니었다.
- 복구 중 빠진 게 있으면(메모리 미연결·레포 부재·시크릿 없음·모델 없음·커맨드 미설치) 그 항목을 콕 집어 알리고, PC면 바로 복구를 제안한다.
- **모바일에서 조종 중일 수 있음을 전제로 가독성을 챙긴다.** 배너는 그대로 두되, 상세 목록이 길면 요약하고 근거는 파일 경로로 가리킨다. 작은 화면에서 스크롤이 길어지면 배너의 값어치가 떨어진다.
  - **`조종` 이 `미상` 이어도 이 원칙은 유지한다** — 미상은 "PC 앞"이라는 뜻이 아니라 **모른다**는 뜻이다. `조종 : 이동 중` 이 명시됐을 때만 더 줄인다.
- ⚠️ **`작업종료` 후에도 세션 창은 닫지 않는다** — 상주 서버가 없어 **PC 에 열려 있는 세션에만 붙는다.** 자리를 떠날 때 창을 남기고 `/clear <머신>-<레포>` 로 이름을 붙이면 모바일 목록에서 알아볼 수 있다(§2 세션 이름 규칙). **이 규칙은 나중에 모바일로 이어갈 때만 의미가 있다** — 그럴 일이 없으면 신경 쓰지 않는다.

| 권한 스코프 | 없음 | **§2 에 실측 표 신설** | 레포별 세션의 이득·손실이 여기서 갈린다. 가산이 아님을 못 박았다 |

⚠️ **"레포별 세션이 항상 낫다"는 아니다.** 허용목록이 cwd 로 정해지므로, 규칙을 쌓아 두지 않은 레포에서 세션을 열면 **루트 세션 때보다 규칙이 줄어든다.** 실측·대책은 이용 가이드 §1-b 와 `[[claude-settings-permission-scope]]`.

⚠️ **서버를 되살리면 이 커맨드가 아니라 가이드 §2 를 본다.** 되살릴 때 배너 `RC` 줄이 다시 필요하면 그때 MINOR 로 되넣는다 — 지금 없는 것을 대비해 남겨 두면 **매 세션 거짓 경고**가 된다.

## v2.4 변경 이력 (v2.3 → v2.4)

- **RC 서버 상태가 배너에 들어왔다** — §2-PC 점검 **6번 신설**, §4 배너 **`RC` 줄 신설**. ⚠️ **v3.0.0 에서 둘 다 제거됐다**(서버 층 중단).
- **발단**: 2026-08-18 회사 PC 재부팅(12:56) 후 RC 서버가 살아나지 않았다. 메모리 노트는 *"2026-08-13 자동시작 실검증 완료"* 로 닫혀 있었는데 **재부팅 한 번을 못 견뎠고**, 그날 세션이 §2 점검을 하다 우연히 발견했다. 발견 전까지의 유일한 신호는 "모바일에서 붙으려다 안 됨"이었다 — **모바일이 필요한 순간에야 알게 되는 구조**였다.
- **왜 커맨드에 넣었는가**: 자동시작 설치는 이 커맨드의 소관이 아니지만, **모바일 경로가 살아 있는지는 세션 시작 시점의 사실**이고 배너는 그런 사실을 모으는 자리다. 대시보드가 아니라 커맨드에 넣은 이유는 — 대시보드는 **골라서** 실행하고, 이 커맨드는 **모든 세션이** 지난다.
- **교훈은 남는다** — *"조용히 실패하는 것은 사람이 아니라 커맨드가 탐지한다."* v3.0 에서 사라진 것은 그 원칙이 아니라 **탐지 대상(서버 프로세스)** 이다.

## v2.3 변경 이력 (v2.2 → v2.3)

- **모바일 경로 교체**: Hermes(Slack 상주 런타임) → **Claude Code Remote Control**. Hermes 는 모델 대화에 HTTP API 엔드포인트가 필수라 종량 결제에 묶여 있었고, 그 비용을 없애기로 하면서 구독 요금 안에서 도는 RC 로 옮겼다(2026-08-13).
- **§2 복구 절이 하나로 합쳐졌다** — RC 세션은 **같은 머신·같은 Claude Code** 다. Hermes 는 별도 에이전트라 커맨드를 스킬로 재이식해야 했지만(정본 개정 때마다 손으로 따라가는 이중 관리), RC 는 이 커맨드가 정본 그대로 돈다. 그래서 PC 절차를 준용하고 **차이 넷**(위치 상수·요청 단위 용도·동시 작업 가드·레포 결정)만 남겼다. ⚠️ v3.0 에서 그 절 자체가 §2 로 일반화됐다.
- §1-3: 환경 차원을 `PC(Local) / PC(Remote Control) / 모바일·웹` 으로 재정의. ⚠️ **v3.0.0 에서 2값으로 재정의됐다.**
- §2-Hermes 의 "런타임/스레드 두 층위", "채널 기본 레포(`channel_repo_map`)", "Chat↔Repo 모드"는 Hermes 고유 개념이라 **삭제**.
- §4: **untracked 스냅샷 감지**를 명시 — 2026-08-10 에 스냅샷이 커밋 없이 3일간 갇힌 사례가 실제로 있었고, HARD-GATE 는 §4에 도달한 세션만 검증하므로 이 감지가 실효 대책이다.
- §2-폴백: Web 세션에 **규칙(rules) 미적용** 경고 추가.
- Hermes 관련 문서는 지우지 않고 동결·보존한다(복구 가능). 근거는 배포처의 결정 기록 참조.

## v2.2 변경 이력 (v2.1 → v2.2)

- §4: 배너에 **`상태`** 줄 신설 — 최신 스냅샷 확장자(`*.ckpt.md`=열림 / `*.md`=닫힘)로 판정.
- §4: **미종료 감지·안내** 규정 추가. 상태는 **레포 단위**, 같은 레포 재시작은 **재개(기본값=이어서 진행)**, 다른 레포로 갈 때는 미종료 레포를 고지. 안내 명분은 "세션을 닫아라"가 아니라 **"메모리 반영이 빠져 다음 판단이 낡는다"**. 권고이며 **차단하지 않는다.**
